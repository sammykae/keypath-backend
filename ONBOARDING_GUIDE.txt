==============================================================
  KEYPATH — FULL ONBOARDING API GUIDE
  Base URL: http://localhost:3001
  All requests: Content-Type: application/json
  Auth header:  Authorization: Bearer <token>
==============================================================


================================================================
  STEP 0 — SHARED AUTH ENDPOINTS (all roles start here)
================================================================

-- LOGIN --
POST /api/auth/login
Body:
{
  "email": "user@example.com",
  "password": "YourPassword123!"
}
Response gives: token, user.role, dashboardRoute

-- GET PROFILE --
GET /api/auth/me/profile
Header: Authorization: Bearer <token>
Returns: profile + role-specific sub-doc (tenantProfile / landlordProfile / communityProfile / investorProfile)

-- VERIFY EMAIL (after registration) --
GET /api/auth/verify-email?token=<token_from_email>

-- RESEND VERIFICATION EMAIL --
POST /api/auth/verify-email/resend
Header: Authorization: Bearer <token>


================================================================
  FLOW 1 — COMMUNITY STAKEHOLDER (self-serve, no invite needed)
  Roles: COMMUNITY, COMMUNITY_STAKEHOLDER
================================================================

STEP 1 — Create account
POST /api/auth/register
Body:
{
  "email": "sarah@kumasi.gov.gh",
  "password": "SecurePass1!",
  "role": "COMMUNITY_STAKEHOLDER",
  "firstName": "Sarah",
  "lastName": "Osei"
}
Response: { token, user, dashboardRoute: "/community", nextStep: "verify_email" }
→ Save the token for all following requests.

--------------------------------------------------------------
STEP 2 — Set up org profile
POST /api/auth/me/setup
Header: Authorization: Bearer <token>
Body:
{
  "firstName": "Sarah",
  "lastName": "Osei",
  "orgName": "City of Kumasi",
  "orgType": "municipality",
  "phone": "+233501234567",
  "website": "https://kumasi.gov.gh",
  "country": "Ghana"
}
orgType options: "municipality" | "school" | "nonprofit" | "other"

--------------------------------------------------------------
STEP 3 — Save organization information (onboarding wizard step)

Header: Authorization: Bearer <token>

{
  "organizationName": "City of Kumasi",

  "jurisdiction": "Kumasi, Ashanti Region",
  "role": "Community Liaison"
}

--------------------------------------------------------------
STEP 4 — Save stakeholder type

Header: Authorization: Bearer <token>

  "stakeholderType": "MUNICIPALITY"
}

STEP 5 — Program association

================================================================
  FLOW 3 — TENANT (requires invite from landlord)
================================================================

STEP 1 — Tenant submits interest (optional, admin-initiated flow)
POST /api/onboarding/tenant/interest
Body:
{
  "firstName": "Kwame",
  "lastName": "Mensah",
  "email": "kwame@example.com",
  "phone": "+233201234567",
  "message": "Looking for affordable housing"
}

--------------------------------------------------------------
STEP 2 — Landlord/Admin generates invite link (admin-only)
POST /api/onboarding/admin/tenant/:interestId/generate-link
Header: Authorization: Bearer <admin_token>
→ Returns an onboardingToken invite link sent to tenant email

  — OR — (landlord sends directly)

POST /api/invites
Header: Authorization: Bearer <landlord_token>
Body:
{
  "tenantEmail": "kwame@example.com",
  "propertyId": "<propertyId>",
  "unitId": "<unitId>",
  "participationModel": "BOTH",
  "inviteMethod": "LINK",
  "deliveryMethod": "KEYPATH_EMAIL",
  "leaseStartDate": "2025-08-01T00:00:00.000Z",
  "leaseEndDate": "2026-07-31T00:00:00.000Z"
}

--------------------------------------------------------------
STEP 3 — Tenant previews invite (from email link)
GET /api/invites/accept?token=<invite_token>
Response: { summary: { email, propertyName, unit, leaseStart, leaseEnd } }

--------------------------------------------------------------
STEP 4 — Tenant confirms (accepts magic link → gets JWT)
POST /api/invites/accept
Body:
{
  "token": "<invite_token>"
}
Response: { authToken, dashboardRoute: "/tenant", user }
→ Save authToken.

  — IF LINK EXPIRED — request new link:
POST /api/invites/resend
Body: { "email": "kwame@example.com" }

--------------------------------------------------------------
STEP 5 — Tenant creates account via onboarding token (alternative path)
POST /api/onboarding/tenant/create-account
Body:
{
  "onboardingToken": "<token_from_invite_email>",
  "email": "kwame@example.com",
  "password": "SecurePass1!",
  "firstName": "Kwame",
  "lastName": "Mensah"
}
Response: { token }

--------------------------------------------------------------
STEP 6 — Set up tenant profile
POST /api/auth/me/setup
Header: Authorization: Bearer <token>
Body:
{
  "firstName": "Kwame",
  "lastName": "Mensah",
  "phone": "+233201234567",
  "currentAddress": "12 Ring Road, Accra",

  "emergencyContactPhone": "+233244567890"

================================================================
  ERROR CODES TO KNOW
================================================================

INVITE_EXPIRED         → token is past its expiry date (resendInviteCta: true)
INVITE_INVALID         → token does not exist or was cancelled
INVITE_ALREADY_ACCEPTED → tenant already accepted this invite
VERIFICATION_FAILED    → email verify token is bad or expired
EMAIL_EXISTS           → account already registered with this email
UNAUTHORIZED           → missing or invalid Bearer token
ROLE_NOT_PERMITTED     → role does not have access to this endpoint
MISSING_ORG            → landlord JWT has no orgId (onboarding incomplete)
